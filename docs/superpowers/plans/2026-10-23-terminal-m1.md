# The terminal, milestone 1 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `aria` in a terminal attaches to the dock's own sessions (list, attach, leave without stopping anything, a new
session in the current folder), drawn as the canvas "Aria Terminal".

**Architecture:** The service (`aria dock`) keeps owning every session. A new clients socket lets terminal clients speak
the page's own messages; replies and events fan out to the page and to the clients attached to each session, with
request ids remapped so nobody gets another's answer. The client lives in the `aria` binary (`crates/aria/src/term/`): a
pure state reducer ported from `ui/chat/state.js`, ratatui views tested with `TestBackend`, and a thin event loop.

**Tech Stack:** Rust 2021, ratatui 0.29 + crossterm 0.28 (features `event-stream` off, `bracketed-paste` on),
pulldown-cmark 0.12, unicode-width; serde_json; the existing `aria-core` bridge types.

**Spec:** `docs/superpowers/specs/2026-10-23-terminal-design.md` (milestone 1 = "The service" and "The client"; tasks,
checkpoints/undo, `/context`, verify and the router method are later plans).

## Global Constraints

- Everything in English: code, names, messages, docs, commits. UI copy goes through the client's own `texts.rs` (en, es),
  picked by `settings.assistant.language` like the page.
- Both platforms: every task keeps `sh tools/check-macos.sh` green; a test that depends on keys or paths says which
  platform it covers.
- Fixtures use neutral names only: `/home/ana`, `/home/ana/Projects/checkout-widget`, `acme/checkout-widget`.
- Commits: `feat(term): …`, `feat(sessions): …`, `fix(…)`, `test(…)`, `docs: …`; end with the Co-Authored-By line.
- Palette (24-bit, nearest 256 fallback): ground `#0A0A0C`, text `#D6D6DC`, grey `#8A8A94`, faint `#55555E`, rule
  `#26262B`, accent `#B9A8FF`, green `#8BE0B0`, amber `#F0B44C`, coral `#FF9A8B`.
- Quota colours: normal below 80 %, amber from 80 %, coral from 95 %. Context amber from `compaction.percent − 5`.
- At most `MAX_SESSIONS` (8) regular sessions, as today.
- `display.verbose` defaults to `true`.
- The verbose key is Ctrl+O (Pi's own key for expanding tools; the client is not Pi's TUI, so nothing clashes).
- Ctrl+C and Ctrl+D never stop a session; only `/exit` (and the dock's close) closes one; there is always one session.

## Review Focus

1. **A client and the page using the same request id** (both start at 1): each must get only its own reply. Test:
   `hub_gives_each_requester_its_own_reply` (Task 3).
2. **A client that stops reading** (suspended terminal, Ctrl+Z): the dock must never block; the client is dropped. Test:
   `a_client_that_stops_reading_is_dropped_not_waited_for` (Task 3).
3. **A tiny or resized terminal** (20×5, then 200×60): drawing never panics and the footer cuts from the right. Test:
   `draws_in_a_tiny_terminal_without_panicking` (Task 8).
4. **A session whose folder no longer exists** (deleted, unmounted): Pi starts in the settings' projects folder and the
   conversation gets a notice, nothing crashes. Test: `a_missing_session_folder_falls_back_with_a_notice` (Task 1).
5. **The session you are looking at is closed elsewhere** (the dock's ×): the client goes back to the list with a note,
   never hangs on a dead session. Test: `a_session_closed_elsewhere_returns_to_the_list` (Task 10).

### Task 3: The clients hub

**Files:**
- Create: `crates/aria/src/clients.rs`
- Modify: `crates/aria/src/main.rs` (bind, wire), `crates/aria/src/chat.rs` (`ChatCtx.watchers`, "nobody sees" at ~L1522)

**Interfaces:**
- Produces: `clients::socket_path() -> PathBuf` (`control_socket_path()`'s folder + `clients.sock`);
  `Hub::new(chat: mpsc::Sender<PageMessage>, handlers: Arc<dyn Fn(PageMessage) + Send + Sync>) -> Hub`;
  `Hub::serve(&self, listener: UnixListener)` (a thread per client, JSON lines both ways);
  `Hub::route(&self, message: &DockMessage) -> bool` (delivers to clients, returns whether the page should get it);
  `Watchers` (`Clone`, `fn sees(&self, session: &str) -> bool`) given to `ChatCtx` as `watchers: Watchers`.
- Client-only messages (never forwarded): `{"type":"attach","session":"…"}`, `{"type":"detach"}`,
  `{"type":"focus","focused":bool}`.
- Rules: a client's request ids are rewritten to `(1 << 40) + client_no * 1_000_000 + id` going in and back coming out;
  a reply whose id belongs to a client goes only to it and not to the page; a `session { … }` message goes to the page
  and to clients attached to that session; other messages without a client id go to everyone. Each client has a
  `sync_channel(1024)`; a full one drops the client. Allowed from a client: every `handlers::is_chat` message, plus
  `secretSave` (to `handlers`); anything else is answered `error { code: "not-for-clients" }`. A dialog answered by one
  client: the existing `chatDialogClosed` already reaches the others.
- Seen: `Watchers::sees(session)` is true while a client attached to it reports focus (a client that never reported
  focus counts as focused). "Nobody sees" becomes `!(dock_visible && chat_shown) && !watchers.sees(session)`.

  unread, the 1025th `route` returns at once and the client is gone); `clients_cannot_send_handler_messages`;

### Task 10: The client, end to end

**Files:**
- Modify: `crates/aria/src/term/mod.rs`; Create: `crates/aria/src/term/app.rs`, `crates/aria/src/term/list.rs`

**Interfaces:**
- Consumes: `Link` (Task 6), `Session` (7), `view` (8), `Editor`/`Picker`/`Dialog` (9), `control::ensure_running` (4).
- Produces: `App::update(&mut self, input: Input) -> Vec<Effect>` (pure; `Input::{Key, Mouse, Resize, Focus(bool),

  `term::run()` does the I/O: raw mode, alternate screen, mouse capture, focus change and bracketed paste on; restores

- Behaviour: start on the list (`sessionsLoad`; rows: title or `term.untitled`, folder's last component, `working` /
