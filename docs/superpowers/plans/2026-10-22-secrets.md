# Secrets: the model asks, the keyring keeps, the model never sees — Implementation Plan

**Goal:** the person can hand Aria a password, API key or token without it ever reaching the model: through a card the
model asks for, through a key pasted in the chat that the page catches, or from a file (one Aria finds while reading,
or one the person names). Commands use it as an environment variable; outputs that print it are masked.

**Architecture:** values live in the system keyring Aria already uses (account `user:<name>`), with an index of names
only in `~/.aria/secrets.json`. The value always travels page → dock → keyring, or file → dock → keyring; Pi only
ever gets a name.

- **Card:** the `secrets` extension's `request_secret` opens a Pi dialog (`ctx.ui.input`) whose title is a card of kind
  `secret`. The page shows a password field; on Save it sends the value straight to the dock (`secretSave`, a blocking
  handler), and only once the dock has stored it answers the Pi dialog with `saved` (no value). Waiting, cancelling,
  hidden-tab notifications and timeouts are the dialog machinery's.
- **Pasted in the chat:** before `chatSend`, the page looks for key-shaped strings (`sk-…`, `ghp_…`, `github_pat_…`,
  `xox?-…`, `AKIA…`, `glpat-…`, `AIza…`, JWTs). Found, it asks: keep it safe under a name (the value goes to the
  dock, the message carries `[secret saved as <name>]`), or send as is.
- **In a file:** the `secrets` extension masks, in every tool result, the values of stored secrets, key-shaped
  strings, and the values of secret-named assignments (`*_KEY=`, `*TOKEN*=`, `*SECRET*=`, `*PASSWORD*=`) in env-like
  text, with a note that says where it was and how to keep it (`secret_import`). `secret_import` (and the person naming
  a path) asks the dock, over the jobs socket, to read the file and store the value under a name.
- **Use:** the sandbox's bash and background runs get `ARIA_SECRET_<NAME>` for each stored secret the command names
  (`$ARIA_SECRET_GITHUB_TOKEN`), read with `aria secret` at spawn time (the dock gives Pi `ARIA_EXE`).
- **Memory and settings:** the persona saves the name and purpose to memory, never the value; settings list the names
  and delete one.

Keyring off (`credentials.keyring`): saving refuses with `keyring-off` (the person turns it on).
