# Aria on macOS — implementation plan

> **For agentic workers:** a platform port. Keep the Omarchy path byte-for-byte equivalent in behaviour; the
> same page, core and Pi must run on both. Steps use checkboxes (`- [x]`) because the first pass is built.

**Goal:** `Option + Space` opens Aria's dock on the Mac, the same page and chat run inside it, and the installer
detects macOS and installs a LaunchAgent instead of a systemd unit — without changing the Omarchy build.

**Architecture:** build-time platform selection (`cfg(target_os)`). `aria-mac` is the sibling of
`aria-hyprland` (hotkey, focused screen). `dock/mac.rs` implements the same `Dock` API as `dock/gtk.rs` with an
`NSPanel` + `WKWebView`. `ui.rs` hides GTK's main loop vs `NSApplication`. The installer branches on `uname -s`.

**Spec:** `docs/superpowers/specs/2026-10-18-aria-mac-design.md`. Base design:
`docs/superpowers/specs/2026-10-18-aria-base-design.md` (roadmap, platform layer, installer).

**Tech stack:** Rust 2021, `objc2` 0.6, `objc2-foundation` 0.3, `objc2-app-kit` 0.3, `objc2-web-kit` 0.3,
`block2` 0.6, Carbon (`RegisterEventHotKey`), `WKWebView`/`WKURLSchemeHandler`, `launchctl`. Tests: `cargo test`,
`bun test ui`, POSIX `sh` installer tests.

## Global constraints

- The Omarchy build must still compile and behave as before. `dock/gtk.rs`, `aria-hyprland` and the Linux
  installer branch are not rewritten; they are compiled only on Linux.
- No `sudo`, no Accessibility/Input Monitoring permission, no changes to macOS system configuration. The only
  system files are `~/.local/bin/aria`, `~/Library/LaunchAgents/com.aria.dock.plist`, and `~/.aria/`.
- The page is shared: no platform fork in `ui/`. The dock tells it the shortcut with `DockMessage::Platform`.
- All code, identifiers and docs in English; the UI strings stay in the catalogs (`ui/i18n/en.json`, `es.json`).
- The Mac build is a normal Cargo binary (no bundle) for this pass.

### Task 3: The Mac dock

**Files:** `crates/aria/src/dock/mac.rs`.

- [x] `DockPanel` (`NSPanel` subclass) with `canBecomeKeyWindow = true`, `canBecomeMainWindow = false`.
- [x] Panel: borderless + nonactivating, status level, all spaces + full-screen auxiliary, transparent, 700 px
      on the right of the visible frame, no shadow, hidden until needed.
- [x] `WKWebView` with a transparent background; `AriaSchemeHandler` serves `ui/` as `aria://app/…`;
      `AriaScriptHandler` parses `window.webkit.messageHandlers.aria` into `PageMessage`.
- [x] `Dock` API identical to `gtk.rs`: queue before `Ready`, `Open`/`Close`/`Notice`, problem banner,
      close timer (180 ms), notice timer (8.6 s), re-open mid-close.
- [x] Open: remember the frontmost app, activate Aria, make the panel key, focus the web view. Close: order out
      and reactivate the previous app.
- [x] Page: the veil click sends `closeRequest`; `ob.done.desc` and the notice use the platform shortcut.
- [x] Verified with `ARIA_DEBUG=1`: page ready → `LoadSettings`/`SessionsLoad` (the `aria://` fetch worked),
      `Hidden + Toggle -> Opening -> Open`, `active=true key=true` before and 150 ms after opening.

### Task 7: The project's way of working (after the first pass)

The first pass was built before this plan was written and landed as one commit. This task brings it in line with how
the rest of Aria is built: test first, the page drawn from its components, the behaviour changes written down, and a
fresh review of the whole branch.

- [x] The setup's controls redraw the step through its components again (the in-place `paint*` functions repeated
      the components' markup). Test first: every control redraws the step; a redraw keeps the scroll position.
      Browser checks (`tools/ui-sandbox/check.ts`): a switch flips through a redraw, keeps the scroll and the focus.
- [x] Drawing has no side effects: the setup checks a stored credential when the sign-in step opens, not in `render`.
- [x] The setup changes that also apply to Omarchy are written down (spec, "The setup"): a stored credential is
      validated when the sign-in step opens and the flow goes on by itself; a key or sign-in that just worked goes on
      by itself; a check that cannot reach the provider trusts the stored credential; while editing, nothing moves
      by itself.
- [x] Without bwrap (macOS) the sandbox asks before every command instead of refusing them all
      (`extensions/sandbox/route.ts`, test first). A Seatbelt profile is pending.
- [x] Fresh review of the whole branch, then one fix pass.

Rulings:
- `dock/mac.rs` repeats the queue, generations and notice logic of `dock/gtk.rs`. Sharing it needs the Mac build to
  verify, and this pass was made on Linux, where the macOS code cannot be compiled (ring needs Apple's SDK). Left as
  is and listed in `docs/pending.md`; cost if wrong: a fix to one dock has to be made twice.
