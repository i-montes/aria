# The terminal, milestone 2 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The rest of the terminal: session status in the list, tasks, per-instruction changes and undo, `/context`,
verification after editing, notifications when a turn ends unseen, the method by load — and the review's leftovers.

**Architecture:** Data comes from the dock (session status, checkpoints, notifications, in Rust) or from Pi extensions
(`tasks`, `context`, `verify`, in TypeScript, published as tool results and `setStatus` lines that reach every client);
the terminal client (`crates/aria/src/term/`) only draws. The dock's page does not change its look.

**Tech Stack:** Rust (aria, aria-core), ratatui/crossterm, TypeScript extensions tested with `bun test`, the system `git`
for checkpoints.

**Spec:** `docs/superpowers/specs/2026-10-23-terminal-m2-design.md` (milestone 1:
`docs/superpowers/specs/2026-10-23-terminal-design.md`).

## Global Constraints

- Everything in English; UI words through `term/texts.rs` (en, es) or `ui/i18n`.
- `sh tools/check-macos.sh` green after every task; platform-dependent tests say which platform they cover.
- Neutral fixtures only (`/home/ana`, `acme/checkout-widget`).
- Commits `feat(term|sessions|chat|extensions): …`, `fix(…)`, with the Co-Authored-By line; nothing is pushed.
- The dock's page keeps its look: new dock messages are ignored by it.
- Checkpoints: `~/.aria/checkpoints/<session>/`, files over 5 MB left out, at most 50 kept in the index, never in `$HOME`
  itself; undo refused while a run is going (`busy`).
- Verify: each command at most 5 minutes; one feedback to the model per run; on macOS only `.aria/verify.json`'s
  commands run (there is no box there), on Linux they run inside bwrap with the sandbox's own arguments.
- Esc Esc: two presses within 500 ms while idle. Ctrl+T folds the task strip. Ctrl+L redraws.

## Review Focus

1. **Undo in a folder with files the turn did not create** (the person's own untracked files, a build folder):
   only what changed since the checkpoint moves; nothing else is deleted. Test:
   `undo_touches_only_what_changed_since_the_checkpoint` (Task 4).
2. **A huge project** (node_modules ignored, a 50 MB video untracked): the snapshot leaves the video out and stays
   fast. Test: `big_files_are_left_out_of_a_checkpoint` (Task 4).
3. **Verify in a project whose tests never end**: the 5-minute limit stops it and the run ends with a note, it never
   hangs the session. Test: `a_check_that_runs_too_long_is_stopped` (Task 7).
4. **A notification storm** (several sessions settle at once, unseen): one per session, each replacing its previous.
   Test: `each_session_keeps_one_notification` (Task 8).
5. **Esc pressed once while idle** (no second press): nothing happens; Esc while running still stops the turn. Test:
   `a_single_esc_while_idle_does_nothing` (Task 5).

### Task 4: Checkpoints

**Files:** Create `crates/aria/src/checkpoints.rs`

**Interfaces:**
- Produces: `Checkpoints::open(root: &Path, session: &str, folder: &Path) -> Option<Checkpoints>` (None for `$HOME` or a
  missing folder); `fn take(&self, text: &str) -> io::Result<Checkpoint>`; `fn changes_since(&self, cp: &Checkpoint) ->
  io::Result<Changes { files: u32, added: u32, removed: u32 }>`; `fn restore(&self, cp: &Checkpoint) -> io::Result<()>`;
  `fn list(&self) -> Vec<Checkpoint>` (newest first, at most 50); `Checkpoint { id: String /*commit*/, text, at: i64,
  files: u32 }` kept in `index.json`. All through `git --git-dir <root>/<session> --work-tree <folder>` with `-c
  user.name=aria -c user.email=aria@localhost`; untracked or modified files over 5 MB go to `info/exclude` before
  `add -A`; `.git` always excluded. `changes_since` snapshots the folder into a commit not listed in the index and diffs
  `--numstat`. `restore`: `checkout <id> -- .`, then deletes the files added since (diff-filter=A between the checkpoint
  and a fresh snapshot).
- [ ] Tests (temp folders with real git): `a_checkpoint_and_its_changes`, `undo_touches_only_what_changed_since_the_checkpoint`
  (a file the person had before, untracked and ignored-by-nothing, survives; a new file goes; an edited one comes back;
  a deleted one returns), `big_files_are_left_out_of_a_checkpoint` (a 6 MB file not in the commit), `no_checkpoints_in_home`,
  `the_list_keeps_fifty`.
- [ ] Implement; tests green; commit `feat(sessions): checkpoints of a session's folder`.

### Task 5: Changes and undo

**Files:** `crates/aria-core/src/bridge.rs`, `crates/aria/src/chat.rs`, `crates/aria/src/clients.rs` (allowed),
`crates/aria/src/term/{app.rs,state.rs,view.rs}`

**Interfaces:**
- Consumes: Task 4's `Checkpoints`.
- Produces: inside `session`: `PageMessage::ChatCheckpoints { id }` → `DockMessage::Checkpoints { id, list }`;
  `PageMessage::ChatUndo { id, checkpoint: String }` → `saved` or `error { code: busy|failed }`. The chat takes a
  checkpoint before a `chatSend` without behavior reaches Pi (and for a queued one, at its `message_start`), and at
  `agent_settled` sends `chatEvent { type: "changes", files, added, removed }` when files > 0. Undo restores files, then
  Pi `get_fork_messages` → the latest entry whose text is the checkpoint's → `fork { entryId }` → `get_state` → the new
  session id appended to the tab's segments (as a rotation) → `chatLoad`-like replay. Client: `Entry::Changes { files,
  added, removed }` drawn `  3 files changed  +40 −12`; Esc Esc (idle, ≤ 500 ms apart) and `/undo` → `chatCheckpoints`
  → a list in the editor's place (`Picker` rows `text · hace 2 min · 3 archivos`), Enter → `chatUndo`; on `saved` the
  editor gets the message's text back.
- [ ] Tests: chat `a_turn_that_changed_files_says_how_many` (fake Pi writes a file in its folder on a `write-file` raw
  command), `undo_puts_files_and_conversation_back` (fake Pi answers `get_fork_messages` and `fork`),
  `undo_is_refused_while_running`; app `esc_esc_opens_the_undo_list`, `a_single_esc_while_idle_does_nothing`,
  `picking_a_checkpoint_undoes_and_gives_the_text_back`.
- [ ] Implement (fake_pi.sh gains `get_fork_messages`, `fork` and `write-file`); tests green; commit

### Task 7: `/context` and verify

**Files:** Create `extensions/context/{index.ts,measure.ts,measure.test.ts}`, `extensions/verify/{index.ts,checks.ts,
checks.test.ts}`; modify `crates/aria/src/term/{state.rs,view.rs,app.rs}`, `crates/aria/src/clients.rs` (piCommand
`get_session_stats` already allowed), `extensions/README.md`

**Interfaces:**
- `context`: at `before_agent_start` measures `{ system, tools, skills, memory, messages }` in tokens (chars / 4) and
  `ctx.ui.setStatus('aria-context', JSON)`. Client keeps the last `aria-context` status (`Session.context_parts`);
  `/context` sends `piCommand get_session_stats` and draws in the editor's place: a grid (width up to 50 cells, one per
  1 % of the window) with a symbol and colour per category (system grey, tools accent, skills green, memory amber,
  messages text, free faint, reserve rule), then rows `● name  12.3k  6%`, the free space and the reserve
  (`compaction.percent`); Esc closes.
- `verify`: `checksFor(folder, platform, hasVerifyJson) -> Check[]` (`.aria/verify.json` `{lint?, types?, test?}` first;
  else on Linux: package.json scripts `lint`, `typecheck`, `test` → `bun run <name>` when a `bun.lock` exists else
  `npm run <name>`; `Cargo.toml` → `cargo clippy -q`, `cargo test -q`; `pyproject.toml` → `ruff check`, `pytest -q`; on
  macOS without verify.json: none). At `agent_end` when the run called `edit` or `write`: runs them in order (Linux:
  `bwrap` with the sandbox's `bwrapArgs` for the folder), 5-minute limit each, stops at the first failure; all passed →
  `setStatus('aria-verify', '{"ok":true,"passed":N}')`; a failure → status `{"ok":false}` and, once per run, a follow-up
  `sendUserMessage` with the command and its last 40 lines; `/verify on|off` per session. Client footer: `tests ✓` /
  `tests ✗` from `aria-verify`.
- [ ] Tests: `bun test extensions/context extensions/verify` (`measures_each_part`, `checks_are_found_per_project`,
  `mac_runs_only_verify_json`, `a_check_that_runs_too_long_is_stopped` (limit injected as 200 ms, `sleep 5`),
  `a_failure_is_fed_back_once`); client `the_context_panel_draws_the_grid_and_rows`, `the_footer_says_how_the_checks_went`.
- [ ] Implement; tests green; commit `feat(extensions): /context and checks after editing`.
