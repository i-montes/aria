# Aria

A personal assistant that lives on your desktop. Press **Super + A** and a dock opens over whatever you are doing, on the monitor you are looking at, to work with your files and tasks and to talk to you in your language.

> **Status: phase 2 of 5, part 2a.** Aria installs, opens with its hotkey, runs the first-run setup, and the dock is now a chat backed by its own pinned [Pi](https://github.com/earendil-works/pi) engine, working in the folder shown at the top of the dock. `/connect` connects a provider from the chat (Anthropic with your Claude plan or an API key, or OpenCode Go). The `+` opens another session as a tab (up to eight, each with its own Pi, so a background tab keeps working and tells you when it needs you). Your extensions, the settings-to-Pi sync and the parity check are the next parts. See [the roadmap](docs/superpowers/specs/2026-10-18-aria-base-design.md#roadmap) and [phase 2](docs/superpowers/specs/2026-10-18-aria-phase2-parity-design.md).

Supported today: **Omarchy** (Hyprland 0.56+ with the Lua configuration). Mac is next.

## Install

```sh
curl -fsSL https://<your site>/install.sh | sh
```

The installer needs **Node 22.19 or newer** (it checks, and says so if not). It adds Aria's system libraries (it asks for `sudo` only if they are missing), puts the `aria` binary in `~/.local/bin`, creates `~/.aria/`, installs the pinned Pi engine in `~/.aria/pi/<version>` and a systemd user unit that starts the dock at login. It **never edits `~/.config/hypr/`**: Aria registers Super + A with Hyprland itself each time it starts.

Run it again to update. To remove Aria: `sh install.sh --uninstall` (it asks before deleting `~/.aria`). Add `--dry-run` to any command to see what would happen without changing anything.

### Build it yourself

You need Rust, `bun` (for the UI tests), and the libraries `gtk3`, `webkit2gtk-4.1` and `gtk-layer-shell`.

```sh
cargo build --release
sh install/install.sh --local target/release/aria
```

## Where things live

| Path | What |
|---|---|
| `~/.aria/settings.json` | Every setting of the project, in one file ([reference](docs/settings.md)) |
| `~/.aria/auth.json` | Credentials, mode `600`, in Pi's format |
| `~/.aria/mcp.json`, `mcp-auth.json` | Notion and Tavily, once you connect them in the setup (Pi's MCP formats, mode `600`) |
| `~/.aria/sessions.json` | The open session tabs (ids, titles, the active one); the conversations are Pi's session files in `~/.aria/agent/sessions` |
| `~/.aria/pi/<version>/` | The pinned Pi engine (the version is in the repo's `pi-version` file) |
| `~/.aria/agent/` | Pi's own directory, regenerated by Aria: its settings, links to the credential files, the persona, sessions |
| `~/.aria/bin/` | `pi` (a shim to the pinned version, for Pi's own subagents) and `node` (a link the service uses) |
| `~/.local/bin/aria` | The binary |
| `~/.config/systemd/user/aria.service` | Starts the dock at login |

The repository only holds code; your data never lives in it.

## Repository layout

```
crates/aria-core/      what does not depend on the system: paths, settings, credentials, providers,
                       key validation, Anthropic sign-in, the dock <-> page messages
crates/aria-hyprland/  the hotkey, the focused monitor and reload events, through Hyprland's own IPC
crates/aria-engine/    Pi's RPC protocol and the supervised Pi child process
crates/aria/           the `aria` binary: the dock window, the chat and the glue between the crates
agent-files/           the owner's persona and experts, written into Aria's Pi
extensions/            the owner's Pi extensions, adapted to run in Aria (see its README)
ui/                    the dock's web page: plain HTML, CSS and JS modules, embedded in the binary;
                       ui/chat/parts/ holds one module per component of the design
tools/ui-sandbox/      the page without Pi, to see and try every chat state
install/               the installer and the systemd unit
design/                the visual reference (Aria.html) and its components
docs/                  how the pieces fit, the settings, how to add a provider, what is still pending (docs/pending.md)
```

Start with [docs/architecture.md](docs/architecture.md).

## Development

```sh
bun tools/ui-sandbox/serve.ts      # the dock's page with a stubbed bridge and the design's simulate buttons (permission, quota, ask, tools, tabs…)
bun tools/ui-sandbox/check.ts      # drives the chat in headless Chrome against it: queue, focus, Esc order, pickers, question card
cargo test --workspace      # Rust: core, Hyprland, engine, dock
cargo test -p aria --test live_pi -- --ignored   # the real Pi answering a prompt (needs the setup done)
bun test ui                 # the UI's logic and its strings
bun test extensions         # the owner's Pi extensions that run inside Aria
sh install/install.test.sh  # the installer, without touching your system
ARIA_DEBUG=1 target/release/aria   # logs state changes and the page's console to the terminal
ARIA_HOME=$(mktemp -d) target/release/aria   # try a first run without touching ~/.aria
```

## Contributing a provider or a platform

- A provider is one module: [docs/adding-a-provider.md](docs/adding-a-provider.md).
- A platform (Mac, other Linux compositors) needs the three things `aria-hyprland` does today: a global hotkey, the focused monitor, and a floating panel that takes the keyboard when it opens.
